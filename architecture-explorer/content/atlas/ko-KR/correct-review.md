## 새 해석은 어떻게 받아들이나요?

```diagram
기존 진술 + 새 근거
↓ 변경 후보 제출
별도 검토 → 승인 또는 거절
```

새 내용도 검토 없이 정식 지식이 되면 안 됩니다. 무엇을 바꾸려는지와 근거를 명시하고 검토합니다. 검토 절차의 존재가 모든 정정 동작의 검증 완료를 뜻하지는 않습니다.

텔레그램의 첫 알림에 전체 변경 내용과 근거 자료가 함께 도착합니다. 자료를 읽고 **승인/반려**를 한 번 선택합니다. 본인 계정 연결과 로컬 프로그램 실행이 필요합니다. 일반 `/start`만 보내는 것은 본인 연결이 아닙니다. 승인 로직과 이력은 기존 지식 서비스가 담당합니다. 외부 작업 승인은 실제 실행과 별개입니다. 현재 터미널 실행 방식에서는 프로그램이 종료되거나 맥이 잠들면 처리가 지연됩니다.

### 왜 이 책임이 필요한가

추출과 사실을 구별하고 불변 검토 결과를 남깁니다. 쓰기 트랜잭션 안에서 근거 접근을 재검사합니다.

### 입력과 출력

입력: 타입 지정 후보, 생성자 접근 맥락, 검토자 식별과 결정.

출력: 불변 승인·거절 결과 하나와 승인 시 정식 기록.

### 무엇을 보존하는가

- Proposal 식별·내용, SUPPORTED_BY 계보, Approval 이력.
- MCP는 승인·거절할 수 없습니다. 대기 제안에 충돌하는 결과를 만들 수 없습니다. 현재 근거 ACL로 권한을 판단합니다.

### 예시를 따라가 보기

검토자는 메모를 실제로 읽을 수 있어야 하며 후보와 근거를 비교합니다. MCP로 후보를 제출한 AI가 이 승인을 대신하지 않습니다.

### 혼동하지 말아야 할 점
