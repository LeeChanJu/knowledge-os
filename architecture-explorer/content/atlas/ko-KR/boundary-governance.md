구현 기술이 바뀌어도 검토와 승인의 약속은 유지합니다. MCP와 REST는 이 약속에 접근하는 어댑터입니다. 자세한 입력·출력과 제약은 계약 레지스트리에서 확인합니다.

<!-- DEPTH -->

### 왜 이 책임이 필요한가

REST·MCP·저장 어댑터·UI와 독립적인 안정 경계를 정의합니다.

### 입력과 출력

입력: 근거 있는 후보와 명시적인 검토 맥락.

출력: 불변 결정과 승인된 정식 기록.

### 무엇을 보존하는가

- Governance 계약 버전.
- Proposal → 검증 → Approval/거절 → 정식 그래프.

### 예시를 따라가 보기

메모의 제공자가 바뀌어도 원본 식별·근거·승인 경계를 다시 정의하지 않습니다. 실제 부족함이 측정될 때 계약과 설계 변경을 검토합니다.

### 혼동하지 말아야 할 점

Proposal → 검증 → Approval/거절 → 정식 그래프.
