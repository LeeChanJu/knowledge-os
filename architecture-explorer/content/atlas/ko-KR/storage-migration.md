마이그레이션은 제약·인덱스 등 구조를 바꾸는 절차입니다. 이미 적용한 파일은 몰래 고치지 않고 Git과 적용 체크섬을 비교합니다.

<!-- DEPTH -->

### 왜 이 책임이 필요한가

스키마를 명시적으로 발전시키고 누락·변경·예상 밖 마이그레이션을 감지합니다.

### 입력과 출력

입력: Git 관리 Cypher와 현재 SchemaMigration 원장.

출력: 적용한 스키마·보완 작업과 기록한 체크섬.

### 무엇을 보존하는가

- Neo4j의 SchemaMigration 기록. Git의 마이그레이션 파일이 기준입니다.
- 적용된 마이그레이션을 조용히 수정하지 않습니다. Explorer는 파일을 읽지만 실행하지 않습니다.

### 예시를 따라가 보기

인덱스를 추가하는 작업과 과거 메모의 잘못된 메타데이터를 교정하는 작업을 구별합니다. 이미 적용한 마이그레이션을 몰래 고쳐 해결하지 않습니다.

### 혼동하지 말아야 할 점

적용된 마이그레이션을 조용히 수정하지 않습니다. Explorer는 파일을 읽지만 실행하지 않습니다.
