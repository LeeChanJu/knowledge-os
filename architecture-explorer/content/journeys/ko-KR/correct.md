## 문서가 바뀐 건가요, 이해가 틀린 건가요?

```diagram
원본에 새 내용이 생김 → 새 관찰
예전 해석이 잘못됨 → 지식 정정 후보
둘을 구별하고 기존 근거 확인
```

원본 변경과 지식 정정은 같은 작업이 아닙니다. 무엇이 바뀌었는지에 따라 새로운 문서 상태를 보존하거나 받아들인 말을 다시 검토합니다. 기존 기록을 먼저 확인해야 무엇을 고치는지 알 수 있습니다.

<!-- stage:version -->
## 왜 예전 내용을 그대로 바꾸지 않을까요?

```diagram
어제: 검토 중 → 당시 근거 유지
오늘: 검토 중단 → 새 상태 기록
이전 답변은 이전 근거를 계속 가리킴
```

예전 기록을 바꾸면 과거 답변의 이유를 잃습니다. 새 상태를 구별하고 이전 근거의 식별을 유지합니다. 단순한 원본 수정이 과거의 모든 지식 판단을 자동으로 정정하는 것은 아닙니다.

<!-- stage:review -->
## 새 해석은 어떻게 받아들이나요?

```diagram
기존 진술 + 새 근거
↓ 변경 후보 제출
별도 검토 → 승인 또는 거절
```

새 내용도 검토 없이 정식 지식이 되면 안 됩니다. 무엇을 바꾸려는지와 근거를 명시하고 검토합니다. 검토 절차의 존재가 모든 정정 동작의 검증 완료를 뜻하지는 않습니다.

<!-- stage:history -->
## 언제 맞았던 말인지도 남길까요?

```diagram
이전 진술 → 당시 적용 기간
↓ 새 진술과 대체·정정 연결
과거 기록 보존 + 현재 판단 구분
```

새 말이 이전 말을 대체해도 이전 기록의 근거와 시점을 잃어서는 안 됩니다. 적용 기간과 기록한 시각은 서로 다릅니다. 현재 시간·정정 및 복구 검증에는 열린 항목이 있으므로 완전한 자동 정정을 약속하지 않습니다.
