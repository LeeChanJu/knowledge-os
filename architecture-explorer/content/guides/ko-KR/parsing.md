지원하는 파일 형식을 수집할 수 있는 텍스트로 변환합니다.

## 이 단계에서 생기는 문제

지원하는 파일 형식을 수집할 수 있는 텍스트로 변환합니다. 전체 문서 여정의 한 부분으로 이해하면 됩니다. 파일의 배치 형식과 텍스트는 서로 다른 표현이기 때문입니다.

## 한 메모를 따라가 보기

내보낸 메모에서 문장을 읽을 수 있게 풀어도 두 기술이 어떤 관계인지는 아직 판단하지 않았습니다. 형식 해석과 지식 판단은 다른 일입니다.

## 개념과 구현을 구분하기

아래의 정확한 저장소 참조를 따라 확인할 수 있습니다. 참조가 존재한다고 새로운 실행 검증 결과가 되는 것은 아닙니다.

기존 파일 어댑터가 문서화된 텍스트 형식과 선택적인 PDF/DOCX 의존성을 지원합니다.

## 구현이 지켜야 할 경계

- 처리 버전은 근거 식별에 참여합니다. 대화록의 시간 표시는 근거 텍스트에 남깁니다.

## 입력·출력·데이터 책임

- 지원하는 파일 바이트 또는 제공자 블록·속성.
- 텍스트, 제목, URI, 파서 버전.
- 별도 저장소 없이 수집으로 텍스트를 전달합니다.

## 비슷해 보이는 개념 비교

| 구분 | 답하는 질문 / 역할 | 주의할 경계 |
|---|---|---|
| 관찰·형식 처리 | 원문 상태를 읽어 근거로 보존 | 원문을 조용히 바꾸지 않음 |
| 의미 판단·검토 | 내용에서 받아들일 말을 결정 | 후보와 승인 경계 필요 |

### 파일을 읽고 나누는 작업이 끝나면 의미 관계도 모두 승인된 것인가요?

아닙니다. 근거 보존과 의미 판단은 다릅니다. 지식 후보를 근거·규칙과 비교하고 별도로 승인해야 합니다.

### 코드나 테스트 파일이 존재한다는 것만으로 이 기능을 믿어도 될까요?

아닙니다. 아래 연결된 테스트의 실행 결과·리비전·환경·검증 범위를 확인해야 합니다. 열린 문제와 보류 범위를 제외하고 판단하며, 이 문서 탐색은 운영 테스트를 실행하지 않습니다.
