## 이 단계에서 생기는 문제

관찰하는 원본의 식별과 연결기 결합 정보를 관리합니다. 전체 문서 여정의 한 부분으로 이해하면 됩니다. 안정된 경계로 다른 어댑터가 원본을 조용히 넘겨받는 일을 막습니다.

## 한 메모를 따라가 보기

폴더 목록을 읽다 오류가 났다고 보이지 않은 메모를 삭제 처리하면 안 됩니다. 전체 목록을 확인한 뒤 변경을 만들고, 커밋 후 체크포인트를 기록합니다.

## 개념과 구현을 구분하기

아래의 정확한 저장소 참조를 따라 확인할 수 있습니다. 참조가 존재한다고 새로운 실행 검증 결과가 되는 것은 아닙니다.

최초 수집에서 안정된 연결기 인스턴스를 결합합니다. 실행이 커밋되어야 체크포인트가 전진합니다.

## 구현이 지켜야 할 경계

- 재시도는 같은 의미 상태를 재현해야 합니다. 제공자 실패를 성공한 빈 목록으로 해석하면 안 됩니다.

## 입력·출력·데이터 책임

- 제공자 목록, 원본 권한, 이전 연결기 체크포인트.
- 결정적인 UPSERT/TOMBSTONE manifest와 다음 체크포인트 후보.
- 어댑터 로컬 체크포인트 파일. 정식 의미 지식은 소유하지 않습니다.

## 비슷해 보이는 개념 비교

| 구분 | 답하는 질문 / 역할 | 주의할 경계 |
|---|---|---|
| 관찰·형식 처리 | 원문 상태를 읽어 근거로 보존 | 원문을 조용히 바꾸지 않음 |
| 의미 판단·검토 | 내용에서 받아들일 말을 결정 | 후보와 승인 경계 필요 |

### 파일을 읽고 나누는 작업이 끝나면 의미 관계도 모두 승인된 것인가요?

아닙니다. 근거 보존과 의미 판단은 다릅니다. 지식 후보를 근거·규칙과 비교하고 별도로 승인해야 합니다.

### 코드나 테스트 파일이 존재한다는 것만으로 이 기능을 믿어도 될까요?

아닙니다. 아래 연결된 테스트의 실행 결과·리비전·환경·검증 범위를 확인해야 합니다. 열린 문제와 보류 범위를 제외하고 판단하며, 이 문서 탐색은 운영 테스트를 실행하지 않습니다.
