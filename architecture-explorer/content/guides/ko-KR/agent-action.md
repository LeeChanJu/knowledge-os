변경 하나를 원본부터 근거와 결과까지 따라가 봅니다.

## 이 단계에서 생기는 문제

단계를 순서대로 읽어 보세요. 각 단계의 책임은 다르며 화살표가 모든 단계의 자동 실행을 뜻하지는 않습니다. 식별·이력·권한을 보존해야 나중의 설명을 추적할 수 있습니다.

## 한 메모를 따라가 보기

같은 제목의 메모가 두 연결에 있을 때 제목만으로 합치지 않습니다. 어느 작업공간·원본·연결기에서 관찰했는지가 식별의 일부입니다.

## 개념과 구현을 구분하기

확인된 스냅샷을 설명하는 안내이며 실행한 통합 테스트가 아닙니다. 미해결 항목과 유보된 제공자의 한계가 그대로 적용됩니다.

아래 흐름을 따라가며 각 단계를 열어 아키텍처를 확인하세요.

## 구현이 지켜야 할 경계

- 다른 연결기가 소유권을 조용히 가져갈 수 없습니다. 항목 수집만으로 완료 실행의 체크포인트를 전진시키지 않습니다.

## 입력·출력·데이터 책임

- 작업공간, 원본 유형, 불투명 외부 ID, 연결기 ID.
- 안정된 Source 식별과 권한 있는 목록·체크포인트 요약.
- Source 노드, 연결기 결합, 커밋된 동기화 커서.

## 비슷해 보이는 개념 비교

| 구분 | 답하는 질문 / 역할 | 주의할 경계 |
|---|---|---|
| 결정 | 무엇을 하기로 받아들였는가 | 근거와 판단 이력 |
| 실행 요청 | 원본에 어떤 변경을 요청하는가 | 별도 정책·승인·실행 권한 |

### 검토자가 지식 후보를 승인하면 Notion 변경도 자동으로 실행되나요?

아닙니다. 외부 변경은 승인된 구체적 요청과 정책, 인증된 실행 어댑터가 필요합니다. 실행 시도와 외부 성공 결과도 구분합니다.

### 코드나 테스트 파일이 존재한다는 것만으로 이 기능을 믿어도 될까요?

아닙니다. 아래 연결된 테스트의 실행 결과·리비전·환경·검증 범위를 확인해야 합니다. 열린 문제와 보류 범위를 제외하고 판단하며, 이 문서 탐색은 운영 테스트를 실행하지 않습니다.
