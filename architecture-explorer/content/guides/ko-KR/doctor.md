## 이 단계에서 생기는 문제

무결성 문제를 보고하되 직접 고치지 않는 읽기 전용 점검입니다. 전체 문서 여정의 한 부분으로 이해하면 됩니다. 문제를 찾는 과정에서 과거 데이터를 조용히 다시 쓰지 않도록 합니다.

## 한 메모를 따라가 보기

메모 검색이 성공해도 연결이 빠졌거나 해시가 틀릴 수 있습니다. Doctor의 구조 검사와 사용자의 질문 답변 품질을 구별해야 합니다.

## 개념과 구현을 구분하기

아래의 정확한 저장소 참조를 따라 확인할 수 있습니다. 참조가 존재한다고 새로운 실행 검증 결과가 되는 것은 아닙니다.

Doctor는 그래프 계보, 마이그레이션·인덱스 상태, SQLite 무결성을 점검합니다. 남은 검사 범위 문제는 F3에 기록합니다.

## 구현이 지켜야 할 경계

- 탐지와 정정을 구분합니다. F3에는 검사 범위·호환성 미해결 사례가 있습니다.

## 입력·출력·데이터 책임

- 기존 그래프, 마이그레이션 파일, 운영 저장소.
- 범위가 제한된 무결성 보고서.
- 복구 상태를 소유하지 않습니다.

## 비슷해 보이는 개념 비교

| 구분 | 답하는 질문 / 역할 | 주의할 경계 |
|---|---|---|
| 테스트 | 코드가 기대대로 동작하는가 | 정해진 입력과 실패 조건 |
| Doctor | 저장 상태에 구조적 손상이 있는가 | 계보·스키마 등 검사 |
| 평가 | 검색 품질과 권한 경계가 충분한가 | 질문 세트와 원시 결과 검사 |

### 검색이 성공하거나 점수가 좋아도 무엇이 여전히 잘못될 수 있나요?

계보 손상이나 권한 누출은 별도 검사해야 합니다. F3·F7 같은 열린 범위를 전체 품질 점수로 가리면 안 됩니다.

### 코드나 테스트 파일이 존재한다는 것만으로 이 기능을 믿어도 될까요?

아닙니다. 아래 연결된 테스트의 실행 결과·리비전·환경·검증 범위를 확인해야 합니다. 열린 문제와 보류 범위를 제외하고 판단하며, 이 문서 탐색은 운영 테스트를 실행하지 않습니다.
