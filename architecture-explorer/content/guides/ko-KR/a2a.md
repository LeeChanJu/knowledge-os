## 이 단계에서 생기는 문제

향후 검토할 에이전트 간 통합 방향입니다. 전체 문서 여정의 한 부분으로 이해하면 됩니다. 새 프로토콜은 존재한다는 이유가 아니라 측정된 필요가 있어야 도입합니다.

## 한 메모를 따라가 보기

메모의 제공자가 바뀌어도 원본 식별·근거·승인 경계를 다시 정의하지 않습니다. 실제 부족함이 측정될 때 계약과 설계 변경을 검토합니다.

## 개념과 구현을 구분하기

아래의 정확한 저장소 참조를 따라 확인할 수 있습니다. 참조가 존재한다고 새로운 실행 검증 결과가 되는 것은 아닙니다.

A2A 운영 통합은 의도적으로 유보되어 있습니다. 현재 접근은 기존 API/MCP 경계를 사용합니다.

## 구현이 지켜야 할 경계

- 제공자 재시도로 의미 상태가 중복되면 안 됩니다.

## 입력·출력·데이터 책임

- 안정 식별과 권한이 있는 제공자 관찰.
- 버전 근거와 커밋된 원본 실행 이력.
- Source 계약 버전. 운영 데이터는 Neo4j에 있습니다.

## 비슷해 보이는 개념 비교

| 구분 | 답하는 질문 / 역할 | 주의할 경계 |
|---|---|---|
| 어댑터 | 외부 요청을 정해진 계약으로 전달 | MCP·REST는 교체 가능 |
| 안정 계약 | 무엇을 읽고 제안·실행할 수 있는가 | 계보·권한·승인 경계 유지 |

### MCP에 연결한 AI가 임의 Cypher나 승인 권한을 얻는가요?

아닙니다. 어댑터는 정해진 요청만 전달합니다. 직접 DB 탐색·지식 승인·외부 실행은 연결 자체로 허용되지 않습니다.

### 코드나 테스트 파일이 존재한다는 것만으로 이 기능을 믿어도 될까요?

아닙니다. 아래 연결된 테스트의 실행 결과·리비전·환경·검증 범위를 확인해야 합니다. 열린 문제와 보류 범위를 제외하고 판단하며, 이 문서 탐색은 운영 테스트를 실행하지 않습니다.
