모델이 답변을 만들기 전에 검색한 근거를 제공하는 방식입니다.

## 이 단계에서 생기는 문제

기억에만 의존하지 않고 책을 펼쳐 근거를 확인하며 답하는 방식과 비슷합니다. 검색은 관련 원본 맥락을 제공하지만 생성된 답변의 정확성을 보장하지는 않습니다.

## 한 메모를 따라가 보기

“Joule”라는 단어를 기억하면 정확한 단어 검색으로 후보를 찾습니다. 결과를 받았어도 인용한 메모가 실제 질문에 답하는지는 별도로 읽어야 합니다.

## 개념과 구현을 구분하기

검색 추적 기록을 이 저장소에서 답변 생성 서비스를 실행했다는 증거로 혼동하면 안 됩니다.

Knowledge OS는 검색과 근거 계약을 제공합니다. 답변은 이를 사용하는 에이전트나 모델이 생성합니다.

## 구현이 지켜야 할 경계

- 결합 과정에서 권한 요구를 버릴 수 없습니다.

## 입력·출력·데이터 책임

- 검색어, 모드, 접근 맥락, 선택적인 벡터·모델·버전.
- 순위가 있는 근거와 추적 ID.
- 추가 인덱스 서비스가 없습니다.

## 벡터 RAG

벡터 유사도로 근거를 검색하는 RAG 방식입니다. 비슷한 의미를 찾은 뒤 해당 문단을 모델에 전달합니다.

에이전트 도구에 관한 질문으로 의미가 비슷한 문단을 찾습니다.

별도 배포 서비스나 검증 완료된 모델 파이프라인이 아니라 검색 패턴을 가리키는 용어입니다.

## 그래프 RAG

그래프 관계를 이용해 맥락을 모으는 RAG 방식입니다. 관련 연결을 따라간 뒤 그 근거를 이용해 설명합니다.

도구와 관련 기술 및 근거 진술을 함께 보면 프로젝트에서의 위치를 설명하는 데 도움이 됩니다.

이 용어가 전체 그래프 요약이나 자율 추론 엔진을 뜻하지는 않습니다.

## 비슷해 보이는 개념 비교

| 구분 | 답하는 질문 / 역할 | 주의할 경계 |
|---|---|---|
| 단어 검색 | 기억나는 표현으로 찾기 | 단어와 권한 필터 |
| 의미 검색 | 비슷한 뜻으로 찾기 | 호환 임베딩과 채워진 자료 필요 |
| 관계 검색 | 기록된 연결을 따라가기 | 승인된 관계와 근거 범위 |

### 벡터 인덱스가 있으면 모든 메모의 의미 검색이 이미 가능한가요?

아닙니다. 호환되는 모델과 임베딩 자료, 검증된 제공자 선택이 별도로 필요합니다. 현재 운영 자료 채움과 제공자 보류 범위를 확인해야 합니다.

### 코드나 테스트 파일이 존재한다는 것만으로 이 기능을 믿어도 될까요?

아닙니다. 아래 연결된 테스트의 실행 결과·리비전·환경·검증 범위를 확인해야 합니다. 열린 문제와 보류 범위를 제외하고 판단하며, 이 문서 탐색은 운영 테스트를 실행하지 않습니다.
