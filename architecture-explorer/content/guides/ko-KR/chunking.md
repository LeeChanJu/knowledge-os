## 이 단계에서 생기는 문제

읽어 낸 텍스트를 개별 근거로 가리킬 수 있는 조각으로 나눕니다. 전체 문서 여정의 한 부분으로 이해하면 됩니다. 반복 가능한 처리로 재시도 시 의미 상태가 중복되는 일을 막습니다.

## 한 메모를 따라가 보기

메모 전체 대신 “검토를 중단했다”는 부분을 정확히 인용합니다. 같은 문장이라도 어느 문서 버전의 어느 부분인지 함께 확인합니다.

## 개념과 구현을 구분하기

아래의 정확한 저장소 참조를 따라 확인할 수 있습니다. 참조가 존재한다고 새로운 실행 검증 결과가 되는 것은 아닙니다.

분할 규칙은 버전이 있고 결정적입니다. 다만 크기 상한 집행은 F6의 미해결 범위입니다.

## 구현이 지켜야 할 경계

- 현재 ACL과 활성 Document 수명주기가 읽기를 통제합니다. 원본이 삭제되어도 과거 Chunk 계보는 유지합니다.

## 입력·출력·데이터 책임

- 버전 식별, 조각 순서, 텍스트, 처리 메타데이터.
- 권한이 허용하는 정확한 근거와 검색 후보.
- 근거 텍스트, 버전 연결, 수명주기 표시, 선택적인 임베딩 계보.

## 비슷해 보이는 개념 비교

| 구분 | 답하는 질문 / 역할 | 주의할 경계 |

| 의미 판단·검토 | 내용에서 받아들일 말을 결정 | 후보와 승인 경계 필요 |

### 파일을 읽고 나누는 작업이 끝나면 의미 관계도 모두 승인된 것인가요?

아닙니다. 근거 보존과 의미 판단은 다릅니다. 지식 후보를 근거·규칙과 비교하고 별도로 승인해야 합니다.

### 코드나 테스트 파일이 존재한다는 것만으로 이 기능을 믿어도 될까요?

아닙니다. 아래 연결된 테스트의 실행 결과·리비전·환경·검증 범위를 확인해야 합니다. 열린 문제와 보류 범위를 제외하고 판단하며, 이 문서 탐색은 운영 테스트를 실행하지 않습니다.
