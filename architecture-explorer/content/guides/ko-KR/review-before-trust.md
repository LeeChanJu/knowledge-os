정해진 검토 절차를 기다리는 지식 변경 후보입니다.

## 이 단계에서 생기는 문제

수정 초안과 승인된 수정은 다릅니다. AI의 제안이 조용히 정식 사실로 바뀌어서는 안 됩니다.

## 한 메모를 따라가 보기

검토자는 메모를 실제로 읽을 수 있어야 하며 후보와 근거를 비교합니다. MCP로 후보를 제출한 AI가 이 승인을 대신하지 않습니다.

## 개념과 구현을 구분하기

같은 내용의 재시도는 같은 수명주기 기록으로 연결됩니다. 근거는 해당 작업공간에 속하고 현재 권한으로 접근 가능해야 합니다.

제안 생성 시 내용 식별과 근거를 연결하고, 승인 또는 거절 결과를 변경 불가능한 기록으로 남깁니다.

## 구현이 지켜야 할 경계

이 문서에서 참조하는 **제안 (Proposal)**의 구현 책임입니다. 개념이나 학습 단계 자체를 별도 서비스로 뜻하는 것은 아닙니다.

- 재시도로 승인·거절된 내용을 다시 열지 않습니다.

## 입력·출력·데이터 책임

이 문서에서 참조하는 **제안 (Proposal)**의 구현 책임입니다. 개념이나 학습 단계 자체를 별도 서비스로 뜻하는 것은 아닙니다.

입력: 후보, 생성자 식별, 온톨로지 버전.

출력: 검토 가능한 불변 후보 식별.

보유 데이터: 내용 해시와 SUPPORTED_BY Chunk 연결.

## 왜 제안과 승인이 필요한가요?

추출한 진술은 후보입니다. 정식 기록으로 반영하기 전에 승인으로 권한 있는 결정을 기록합니다. 기술을 고르기 전에 책임과 근거부터 살펴보세요.

연결된 문서 여정에서 이 경계가 어떻게 작동하는지 확인하세요.

승인된 ADR이 기준입니다. ADR에 추가 이유가 없다면 이 페이지도 더 나아간 주장을 하지 않습니다.

## 비슷해 보이는 개념 비교

| 구분 | 답하는 질문 / 역할 | 주의할 경계 |
|---|---|---|
| 후보 제출 | 이런 내용을 받아들이자고 요청 | 근거와 구조를 갖춤 |
| 승인 | 권한 있는 검토자가 후보를 받아들임 | MCP 제출 권한과 별개 |

## 텔레그램 승인 화면

텔레그램에서는 새 요청의 **검토하기**를 누르고 전체 내용과 근거를 읽은 뒤 **승인/반려**를 선택합니다. 본인 계정 연결과 로컬 프로그램 실행이 필요합니다. 일반 `/start`만 보내는 것은 본인 연결이 아닙니다. 승인 로직과 이력은 기존 지식 서비스가 담당합니다. 외부 작업 승인은 실제 실행과 별개입니다. 현재 터미널 실행 방식에서는 프로그램이 종료되거나 맥이 잠들면 처리가 지연됩니다.

### AI가 후보를 만들고 전송했다면 승인까지 완료된 것인가요?

아닙니다. 후보 제출과 별도 검토는 다른 단계입니다. 검토 시점의 근거 접근 권한과 승인 이력이 필요합니다.

### 코드나 테스트 파일이 존재한다는 것만으로 이 기능을 믿어도 될까요?

아닙니다. 아래 연결된 테스트의 실행 결과·리비전·환경·검증 범위를 확인해야 합니다. 열린 문제와 보류 범위를 제외하고 판단하며, 이 문서 탐색은 운영 테스트를 실행하지 않습니다.
