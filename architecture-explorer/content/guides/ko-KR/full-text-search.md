내용에서 색인한 단어로 텍스트를 찾는 검색입니다.

## 이 단계에서 생기는 문제

책의 찾아보기처럼 특정 용어가 나오는 부분을 찾도록 돕습니다. 정확한 이름이나 특징적인 단어는 유용한 검색 신호가 됩니다.

## 한 메모를 따라가 보기

“Joule”라는 단어를 기억하면 정확한 단어 검색으로 후보를 찾습니다. 결과를 받았어도 인용한 메모가 실제 질문에 답하는지는 별도로 읽어야 합니다.

## 개념과 구현을 구분하기

사용자 입력은 임의의 Lucene 문법이 아니라 단어로 취급합니다. 키워드 순위에는 제목 신호와 초기 문서 다양성도 반영합니다.

Neo4j 전문 검색 후보에 권한 필터와 기존 검색 경로의 순위 처리를 적용합니다.

## 구현이 지켜야 할 경계

이 문서에서 참조하는 **전문 인덱스 (Full-text Index)**의 구현 책임입니다. 개념이나 학습 단계 자체를 별도 서비스로 뜻하는 것은 아닙니다.

- 사용자 검색어가 Lucene 문법이 되어서는 안 됩니다. 후보 순위가 원본 권한을 우회하지 않습니다.

## 입력·출력·데이터 책임

이 문서에서 참조하는 **전문 인덱스 (Full-text Index)**의 구현 책임입니다. 개념이나 학습 단계 자체를 별도 서비스로 뜻하는 것은 아닙니다.

입력: 색인된 Chunk/Entity 텍스트와 문자 그대로 처리한 검색어.

출력: 키워드·엔터티 후보 행.

보유 데이터: chunk_text_fulltext와 entity_name_fulltext 인덱스.

## 비슷해 보이는 개념 비교

| 구분 | 답하는 질문 / 역할 | 주의할 경계 |
|---|---|---|
| 단어 검색 | 기억나는 표현으로 찾기 | 단어와 권한 필터 |
| 의미 검색 | 비슷한 뜻으로 찾기 | 호환 임베딩과 채워진 자료 필요 |
| 관계 검색 | 기록된 연결을 따라가기 | 승인된 관계와 근거 범위 |

### 벡터 인덱스가 있으면 모든 메모의 의미 검색이 이미 가능한가요?

아닙니다. 호환되는 모델과 임베딩 자료, 검증된 제공자 선택이 별도로 필요합니다. 현재 운영 자료 채움과 제공자 보류 범위를 확인해야 합니다.

### 코드나 테스트 파일이 존재한다는 것만으로 이 기능을 믿어도 될까요?

아닙니다. 아래 연결된 테스트의 실행 결과·리비전·환경·검증 범위를 확인해야 합니다. 열린 문제와 보류 범위를 제외하고 판단하며, 이 문서 탐색은 운영 테스트를 실행하지 않습니다.
