숫자 표현 사이의 거리를 이용해 찾는 검색입니다.

## 이 단계에서 생기는 문제

정확히 같은 단어만 찾는 대신 가까운 의미를 찾습니다. 단어가 많이 겹치지 않을 때 추가 검색 신호를 제공합니다.

## 한 메모를 따라가 보기

정확한 단어를 잊었을 때 의미가 비슷한 부분을 찾는 방법을 비교할 수 있습니다. 벡터 인덱스가 있다는 것과 운영 자료의 임베딩이 채워졌다는 것은 다릅니다.

## 개념과 구현을 구분하기

인덱스 지원이 운영 벡터 채우기나 검색 품질 검증을 뜻하지는 않습니다. 모델 호환성과 현재 권한도 중요합니다.

벡터 인덱스는 Neo4j 안에 있으며 외부 벡터 데이터베이스를 따로 두지 않습니다.

## 구현이 지켜야 할 경계

- 제공자 활성화만을 위해 차원을 바꾸지 않습니다. 모델·버전은 질문과 일치해야 합니다. 인덱스가 있다고 벡터가 채워진 것은 아닙니다.

## 입력·출력·데이터 책임

- 모델·버전 정보가 있는 권한 있는 현재 Chunk 벡터.
- 필터링한 의미 검색 후보.
- Chunk 임베딩의 Neo4j 인덱스.

## 비슷해 보이는 개념 비교

| 구분 | 답하는 질문 / 역할 | 주의할 경계 |
|---|---|---|
| 단어 검색 | 기억나는 표현으로 찾기 | 단어와 권한 필터 |
| 의미 검색 | 비슷한 뜻으로 찾기 | 호환 임베딩과 채워진 자료 필요 |
| 관계 검색 | 기록된 연결을 따라가기 | 승인된 관계와 근거 범위 |

### 벡터 인덱스가 있으면 모든 메모의 의미 검색이 이미 가능한가요?

아닙니다. 호환되는 모델과 임베딩 자료, 검증된 제공자 선택이 별도로 필요합니다. 현재 운영 자료 채움과 제공자 보류 범위를 확인해야 합니다.

### 코드나 테스트 파일이 존재한다는 것만으로 이 기능을 믿어도 될까요?

아닙니다. 아래 연결된 테스트의 실행 결과·리비전·환경·검증 범위를 확인해야 합니다. 열린 문제와 보류 범위를 제외하고 판단하며, 이 문서 탐색은 운영 테스트를 실행하지 않습니다.
