작업이 어떻게 동작했는지 설명하는 제한된 운영 기록입니다.

## 이 단계에서 생기는 문제

문서 전체를 복사하지 않아도 시간 측정과 오류 횟수로 과정을 진단할 수 있습니다. 측정한 동작은 실패를 진단하고 변경의 이유를 마련하는 데 도움이 됩니다.

## 한 메모를 따라가 보기

메모의 지식은 저장됐는데 감사 기록에 실패한 경우를 생각해 보세요. 저장 결과를 정확히 알리고 재시도 시 누락된 감사만 보완해야 합니다.

## 개념과 구현을 구분하기

F8은 그래프·감사 기록 실패 복구를 다룹니다. 저장소를 나눴다고 분산 트랜잭션이 생기는 것은 아닙니다.

SQLite에 운영 추적과 제한된 메타데이터를 저장합니다. 어댑터 기록에는 문서 내용이나 자격 증명을 넣지 않습니다.

## 구현이 지켜야 할 경계

- 권한 거부 검사는 제외 처리 전에 유출 결과로 실패해야 합니다. F7이 열려 있습니다. 그래프·감사 복구는 분산 트랜잭션이 아니며 F8이 열려 있습니다.

## 입력·출력·데이터 책임

- 어댑터 시간, 접근 결합 추적 ID, 평가 사례, 피드백.
- 운영 행, 측정한 검색 지표, 진단 기록.
- 기존 로컬 SQLite의 운영 근거.

## 비슷해 보이는 개념 비교

| 구분 | 답하는 질문 / 역할 | 주의할 경계 |
|---|---|---|
| 테스트 | 코드가 기대대로 동작하는가 | 정해진 입력과 실패 조건 |
| Doctor | 저장 상태에 구조적 손상이 있는가 | 계보·스키마 등 검사 |
| 평가 | 검색 품질과 권한 경계가 충분한가 | 질문 세트와 원시 결과 검사 |

### 검색이 성공하거나 점수가 좋아도 무엇이 여전히 잘못될 수 있나요?

계보 손상이나 권한 누출은 별도 검사해야 합니다. F3·F7 같은 열린 범위를 전체 품질 점수로 가리면 안 됩니다.

### 코드나 테스트 파일이 존재한다는 것만으로 이 기능을 믿어도 될까요?

아닙니다. 아래 연결된 테스트의 실행 결과·리비전·환경·검증 범위를 확인해야 합니다. 열린 문제와 보류 범위를 제외하고 판단하며, 이 문서 탐색은 운영 테스트를 실행하지 않습니다.
