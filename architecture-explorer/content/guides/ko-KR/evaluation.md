기대한 동작과 관찰한 동작을 비교한 기록입니다.

## 이 단계에서 생기는 문제

시험에는 문제와 채점 기준이 필요합니다. 한 시험에서 높은 점수를 받았다고 모든 상황을 잘 아는 것은 아닙니다. 근거는 성공 주장을 꾸미는 데 그치지 않고 설계 변경을 이끌고 한계를 드러내야 합니다.

## 한 메모를 따라가 보기

메모의 지식은 저장됐는데 감사 기록에 실패한 경우를 생각해 보세요. 저장 결과를 정확히 알리고 재시도 시 누락된 감사만 보완해야 합니다.

## 개념과 구현을 구분하기

F7은 권한 평가 제외 문제를 다룹니다. 과거 PROVEN 기록이 자동으로 현재 VERIFIED 상태가 되지는 않습니다.

평가 기록은 기존 검색 계약과 SQLite를 사용하며 작업공간과 접근 지문으로 범위를 정합니다.

## 구현이 지켜야 할 경계

이 문서에서 참조하는 **관측과 평가 (Telemetry / Evaluation)**의 구현 책임입니다. 개념이나 학습 단계 자체를 별도 서비스로 뜻하는 것은 아닙니다.

- 권한 거부 검사는 제외 처리 전에 유출 결과로 실패해야 합니다. F7이 열려 있습니다. 그래프·감사 복구는 분산 트랜잭션이 아니며 F8이 열려 있습니다.

## 입력·출력·데이터 책임

이 문서에서 참조하는 **관측과 평가 (Telemetry / Evaluation)**의 구현 책임입니다. 개념이나 학습 단계 자체를 별도 서비스로 뜻하는 것은 아닙니다.

입력: 어댑터 시간, 접근 결합 추적 ID, 평가 사례, 피드백.

출력: 운영 행, 측정한 검색 지표, 진단 기록.

보유 데이터: 기존 로컬 SQLite의 운영 근거.

### 검색이 성공하거나 점수가 좋아도 무엇이 여전히 잘못될 수 있나요?

계보 손상이나 권한 누출은 별도 검사해야 합니다. F3·F7 같은 열린 범위를 전체 품질 점수로 가리면 안 됩니다.

### 코드나 테스트 파일이 존재한다는 것만으로 이 기능을 믿어도 될까요?

아닙니다. 아래 연결된 테스트의 실행 결과·리비전·환경·검증 범위를 확인해야 합니다. 열린 문제와 보류 범위를 제외하고 판단하며, 이 문서 탐색은 운영 테스트를 실행하지 않습니다.
